Hãy thực hiện một **AUDIT TOÀN BỘ LOGIC LUẬN GIẢI TỬ VI hiện đang có trong project**.

## QUY TẮC QUAN TRỌNG

* KHÔNG sửa code.
* KHÔNG refactor.
* KHÔNG thêm AI/Gemini.
* KHÔNG thêm database.
* KHÔNG thay đổi cấu trúc project.
* Chỉ đọc, phân tích và lập tài liệu về logic hiện tại.
* Không suy đoán logic nếu không tìm thấy trong code/data.
* Mọi kết luận phải chỉ rõ file/function/data source làm căn cứ.

Mục tiêu cuối cùng là tạo ra một **bản đồ hoàn chỉnh của hệ thống luận giải hiện tại**, để sau đó có thể tích hợp RAG + Gemini mà không phá logic đang có.

Không được dùng diagram giả định. Chỉ thể hiện những gì thực sự tồn tại.

# 5. AUDIT LOGIC LUẬN GIẢI

Đây là phần QUAN TRỌNG NHẤT.

Tìm toàn bộ nơi project đang biến:

```text
Chart Data
```

thành:

```text
Interpretation
```

Ví dụ tìm các pattern:

```text
if star === ...
if palace === ...
stars.includes(...)
switch(...)
getInterpretation(...)
getMeaning(...)
interpret(...)
analyze(...)
generate...
```

Phải xác định:

### Logic dạng rule

Ví dụ:

```text
Nếu:
Thất Sát tại Tài Bạch

→ lấy interpretation X
```

### Logic kết hợp

Ví dụ:

```text
Thất Sát + Kình Dương
→ interpretation Y
```

### Logic quan hệ cung

Ví dụ:

```text
Tài Bạch
+ Xung chiếu Quan Lộc
+ Tam hợp Phúc Đức
→ interpretation Z
```

### Logic ưu tiên

Nếu nhiều rule cùng match:

```text
Rule A
Rule B
Rule C
```

thì hệ thống đang:

* lấy tất cả?
* lấy rule đầu tiên?
* merge?
* overwrite?
* priority?
* score?

Phải tìm trong code và ghi rõ.

# 10. TÌM LOGIC TRÙNG LẶP

Kiểm tra:

* cùng một sao nhưng có nhiều nguồn luận giải
* cùng một cung nhưng nhiều rule

* logic nằm trong JSON và hard-code

* duplicate rule
